# Boat Manager 1.5.1 — release plan

Drafted 19 September 2026, against `main` of the app repo at `46008ca` ("1.5.0")
and `e6d4c25` of this repo.

## The rule for this release

1.5.1 is a point release behind a shipped 1.5.0. It fixes what 1.5.0 broke or left
unfinished, and adds only what is small enough to be verified in a week. No new
entities, no store migration beyond additive optional attributes, no feature that
needs a season of data to prove itself. Everything else is 1.6.

Two lists were merged to build this: the BoatManager Todoist project (28 open
items) and the unfinished build-order steps in `claude/vsc-feature-spec.md` and
`claude/expenses-feature-spec.md`.

## Tier 1 — Defects. 1.5.1 does not ship without these.

### 1. Upkeep dashboard misses maintenance log entries — L

Todoist: *Check Hull zincs code — upkeep dashboard not finding the log entries*;
*Link equipID rather than link by name*. These are one bug, not two.

The dashboard matches a logged task to a piece of equipment by **string equality
on names**:

- `Boat Manager 2/Shared/UpkeepStatus.swift:259` — `trackerNames.contains(normalized(task.taskName))`
- `UpkeepStatus.swift:261` — the task's equipment list must *contain* the row's equipment name
- `UpkeepStatus.swift:273` — `maintenanceEquip` is a **comma-separated string of equipment names**, split and lowercased
- `Boat Manager 2/Shared/CoreData/CDFunctions.swift:353-372` — `autoLinkMaintenanceItems` links by `equipType` string equality too

Consequences, all silent: rename a piece of equipment and its history detaches;
"Hull Zincs" never matches an item named "Zincs — Hull"; a comma inside an
equipment name splits it into two phantom entries.

Fix: additive optional `equipID` (UUID) on `MaintenanceTasks`, populated on save
and backfilled once at launch from the existing name match, with the name path
kept as the fallback for legacy rows. Additive and optional, so CloudKit is happy
and no migration is needed.

Ship it with a **Data Health finding** — "this task names equipment that matches
nothing" — which is where an owner will actually see the legacy rows that could
not be backfilled. Data Health shipped in 1.5.0 and is the right home.

## Cut from 1.5.1 — and why

**Share an invoice/receipt straight to Expenses** (Todoist p1, filed as a 1.5.1
item). It should not be one. It needs a share-extension target, an expense-entry
path from outside the app, and OCR prefill to be worth more than the existing
workaround. `expenses-feature-spec.md` also says the expense model's own
groundwork — `insuredValue` on `Boat`, `costClass` on `MaintenanceTasks`, the
capital prompt, `RecurringExpense` — comes first, and none of it is built. This
is the opening feature of 1.6, not a patch. Item 7 above delivers the part that
is cheap now.

**Everything else on the Todoist list is 1.6 or later**, and none of it is a
point-release shape:

| Item | Why not now |
| --- | --- |
| Expenses data model + dashboard rework | Nine-section spec, wide-to-narrow migration. A release of its own. |
| Voyages/trips; GPS routes to voyages; cruising log with anchorage notes | New entity plus track import, which the expenses spec records as parked. |
| Crew reminders; crew version of the app | New surface, possibly a second target. |
| User-defined fields | Schema and UI generalisation. |
| Connect to Active Captain | Third-party dependency, needs its own spec. |
| Apple Photos album per boat; lean harder on Apple Reminders | Both are integration questions, both need a spec. |
| Paints/solvents/flammables category | It is the `hazardClass` work. `vsc-feature-spec.md` wants it designed knowing VSC items 15b/15c consume it — do it properly in 1.6. |
| Flow from invoice to expense | Same feature as the cut p1 item. |
| Design discussion with Michael Vivona | Input for the next version, not a release item. |

- **Must ship:** 1, 2, 3, 10, 11

and the dashboard everyone reads. Land it first, with the Data Health finding,
and leave a full week of use on real data before submitting.
